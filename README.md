# Afritop

Buy airtime, data bundles and prepaid electricity for Africa, paid in USDC from your own wallet. Right now that covers Nigeria, Ghana, Kenya and South Africa.

Payments settle on [Arc](https://docs.arc.io), Circle's stablecoin L1, and every transfer is verified on-chain before we deliver anything. Airtime goes out through [Africa's Talking](https://developers.africastalking.com). Data bundles and electricity tokens are generated by our own fulfillment pipeline.

Stack: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4, viem.

## Getting started

```bash
npm install
cp .env.local.example .env.local
npm run dev
```

That's all it takes to run locally. The app works without any API keys; the payment path is simulated until you wire up the real ones. Open http://localhost:3000 and you're in.

## How a payment works

1. Build a top-up in the Buy flow.
2. Hit **Pay with USDC**. Your wallet pops up right away, no redirect. Have several wallets installed? A picker lets you choose (EIP-6963). No wallet at all? The page tells you where to get one.
3. The app asks your wallet to switch to Arc Testnet (it adds the network if it isn't there yet), then sends the exact USDC amount to the receiver.
4. We verify the transfer on-chain (`/api/confirm-usdc`), checking recipient, amount and sender against public RPCs.
5. Once verified, the top-up is delivered and you land on the receipt page.

### The testnet phase

Everything runs on Arc Testnet for now. Unless you set `USDC_RECEIVER`, payments go to a burn address, and a **simulate payment** button is available so you can walk through the whole flow. Grab free testnet USDC from [faucet.circle.com](https://faucet.circle.com). Set `USDC_RECEIVER` to your own EVM address and testnet USDC will land in your wallet instead.

Airtime delivery goes live as soon as you add an Africa's Talking key (`AT_ENV=live`).

> **A note on Arc's USDC:** it's dual-decimal. Native gas uses 18 decimals while the ERC-20 interface (`0x3600…`) uses 6, and the verifier parses standard `Transfer` logs from that wrapper. Before trusting real settlements, run one end-to-end testnet payment (faucet → wallet transfer → `/api/confirm-usdc`).

## Environment variables

| Variable | What it's for |
| --- | --- |
| `USDC_RECEIVER` | Your EVM address for receiving USDC payments. Needed before mainnet. |
| `AT_API_KEY` | Africa's Talking API key. Enables real airtime sends. |
| `AT_USERNAME` | Africa's Talking app username. Use `sandbox` while testing. |
| `AT_ENV` | `sandbox` or `live`. |
| `CIRCLE_API_KEY` | Optional. Enables the Circle hosted checkout as an alternative payment path. |
| `CIRCLE_ENV` | `sandbox` or `live`. Ignored for now: checkout stays on testnet until Arc mainnet ships. |
| `CIRCLE_WEBHOOK_SECRET` | Verifies webhook signatures (HMAC-SHA256). |
| `NEXT_PUBLIC_APP_URL` | Public base URL used for Circle redirects. |

Optional extras the code reads if present: `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` (durable order store instead of the JSON-file fallback) and `AUTH_SECRET` (signs the wallet session cookie; set a real value in production).

**Circle webhook.** Register `POST /api/webhook` in the Circle developer console. A tunnel like ngrok works locally. We listen for `checkout.session.completed` and fulfil the linked order automatically.

> The webhook returns 503 until `CIRCLE_WEBHOOK_SECRET` is set, so forged fulfillment events get rejected. The `/api/purchase` endpoint (the simulated payer) is disabled with a 403 when `CIRCLE_ENV=live`, so in production fulfillment only ever happens through the verified webhook.

## What's real, what's simulated

- **Payments:** real on-chain USDC verification (`/api/confirm-usdc`) via public RPCs on Arc Testnet.
- **Airtime:** real through Africa's Talking once `AT_API_KEY` is set, simulated otherwise.
- **Data bundles & electricity tokens:** simulated for now. The fulfillment logic lives in `lib/fulfill.ts`; that's where you'd plug in a vending partner (VTpass for Nigeria, for example) when you're ready.

## Project layout

```
app/
  page.tsx                    # landing page
  buy/                        # top-up flow with live order summary
  pay/[orderId]/              # connect wallet, pay USDC, confirm
  success/                    # receipt, electricity token, on-chain link
  transactions/               # order history, synced per wallet
  docs/                       # in-app documentation
  api/
    checkout/                 # validate and persist an order
    confirm-usdc/             # verify the transfer on-chain, then fulfil
    purchase/                 # demo simulate, disabled in live mode
    transactions/             # the signed-in wallet's history
    webhook/                  # Circle webhook, HMAC verified
    auth/                     # wallet sign-in and session endpoints
    stats/                    # delivery counts for the homepage chart
    fx-rates/                 # live USD to local-currency rates
lib/
  catalog.ts                  # countries, networks, distributors, bundles
  chains.ts                   # Arc Testnet config, USDC, receiver
  usdc-verify.ts              # on-chain transfer verification (viem)
  africastalking.ts           # airtime client
  circle.ts                   # optional Circle hosted checkout
  fulfill.ts                  # payment to delivery pipeline
  store.ts                    # order store: Redis, then JSON file, then memory
components/
  PayPanel.tsx                # wallet connect / switch / pay / confirm UI
```

## Notes

- Exchange rates in `lib/fx.ts` are indicative. Swap in a live FX feed before going to production.
- Order history uses Upstash Redis when configured, a gitignored JSON file otherwise, and falls back to in-memory when the filesystem isn't writable (which happens on some serverless hosts). For a serious deployment, use a real database.
- Receipts are also saved in the browser, so they survive even when the server store comes up empty. Signing in with your wallet ties your history to an address instead of a device.
